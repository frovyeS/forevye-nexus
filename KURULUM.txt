FOREVYE NEXUS – GITHUB ÜZERİNDEN OTOMATİK KART VERİTABANI DÜZELTMESİ

BU GÜNCELLEME NEYİ ÇÖZER?
Market'te görülen card_schema_missing hatasının nedeni, Worker kodu dağıtılırken kart bakiyesi için gereken D1 migration'larının canlı veritabanına uygulanmamasıdır.

GITHUB DAĞITIM AKIŞI
- .github/workflows/deploy-worker.yml, main/master dalına ilgili dosya değişikliği geldiğinde otomatik çalışır.
- Önce DB binding'ine bağlı canlı D1 veritabanındaki bekleyen migration'ları uygular.
- cards.balance, card_ledger ve shop_card_deliveries yapılarını doğrular.
- Yalnızca bütün kontroller başarılıysa Worker deploy eder.
- Aynı akış Actions > Deploy FOREVYE NEXUS Worker > Run workflow ile elle de başlatılabilir.

BİR KERELİK GITHUB AYARI
forevye-nexus GitHub deposunda Settings > Secrets and variables > Actions bölümüne şu iki Repository secret eklenmelidir:
- CLOUDFLARE_API_TOKEN: Worker ve D1 için yazma yetkili Cloudflare API token'ı.
- CLOUDFLARE_ACCOUNT_ID: forevye-nexus D1 veritabanının bulunduğu Cloudflare hesap kimliği.

Bu iki secret zaten varsa tekrar eklemeyin. Secret değerleri kaynak koda veya bu ZIP'e yazılmaz.

ÖNEMLİ
- D1 verileri silinmez veya sıfırlanmaz.
- Migration işlemi doğrulanmadan Worker yayını yapılmaz.
- Worker dağıtımı başarısızsa GitHub deposundaki Actions günlüğünde ilk hata görünür.
- package.json içindeki deploy komutu da migration + şema kontrolü + Worker deploy sırasını izler; Cloudflare Git entegrasyonunda npm run deploy kullanılırsa aynı koruma devrededir.
- Bu ortamda GitHub deposuna doğrudan commit veya canlı Cloudflare deploy yapılamadı. ZIP, ilgili repository dosyalarının yerine konması için hazırlanmıştır.
